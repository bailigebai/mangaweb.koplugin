## 3. 三种复制方案

| 方案 | 改动与收益 | 维护和稳定性影响 |

| A：复制独立核心，加 MangaWeb 阅读适配（推荐） | 保留已有检测、排序、取景和会话算法；接入现有阅读器和设置 | 改动边界清楚，复用原测试；需严格处理图片与会话的释放次序 |
| B：复制完整 WebDAVManga 阅读器，在 MangaWeb 内适配数据来源 | 更多界面可以直接沿用 | 两套阅读、缓存和设置流程重叠，验证范围大，后续改动容易不一致 |

推荐 A。复制后记录来源版本和文件指纹；算法修改必须有对应回归证据，后续明确选择是否同步改进，不在运行时读取另一插件的目录。

## 4. MangaWeb 分格设计

### 使用流程

阅读设置新增“智能分格”，默认关闭，与参考插件默认一致。开启后长按已显示的整页进入；分格中间点按打开控制，侧边操作前后格。提供“保留周边／独立格／自由视图”、旋转、阅读顺序与操作方向，以及周边显示开关和0／2／5／10%边距，并可退出分格恢复原来的页面位置。

跨过最后一格进入下一张原页；反向跨页进入上一张的最后一格。无可识别分格时适屏显示整页，下一张仍继续尝试检测。自由视图中的拖动和缩放不触发翻页。宽图拆页和按宽显示先转为整页分格，退出后恢复先前状态。

沿用本漫画设置与新漫画默认设置：点按修改当前漫画，长按同时保存为默认。按站点＋漫画ID隔离，最多保存64份漫画配置，超过限额清理最久未使用配置。

### 清晰度与资源管理

- 检测使用有界的整页灰度采样；实际显示从 `cached_raw` 原图裁切，再在屏幕大小的分格缓冲上应用当前去灰、亮度与对比度设置。检测用的480像素图只用于识别。
- 复用现有 KOReader/MuPDF 能力。无法安全裁切时回到整页，并显示可理解的提示。
- 设专门的 MangaWeb 分格适配器负责进入、跨页、退出和设置变更。每次操作绑定当前阅读会话和页面令牌；关闭、跳页或重新处理后，旧回调失效。
- 分格会话拥有分格显示缓冲；整页图像由原阅读器拥有。关闭会话前先让界面脱离借用缓冲；释放只发生一次。
- 原图缓存保持占用保护，直到分格会话和原阅读器都释放。预渲染最多下一格；原有按原页预加载数量继续生效。
- 复用现有同窗口设置页面，避免输入页被盖在下一层。灰度/抖动仅在最终显示缓冲处理，分格画面的有效显示令牌参与刷新计数；设置、暂停、失败与退出不会重复累计。
- 保存设置失败时保留原状态和画面。参数错误、不可用模块和普通 Lua 异常在分格边界处理；不把 `pcall` 当成可捕获原生崩溃的保证。

### 文件范围

新增八个 `mangaweb/panel_*.lua` 副本和一个 `mangaweb/reader_panels.lua` 适配模块；修改 `reader.lua`、`settings.lua`、`ui/webdav_reader_shell.lua` 以及 `ui/koreader.lua` 的接入点。为分格设置新增小控制模块，沿用现有阅读设置模式。仅在必要时补充原图引用保护接口。

复制相应规格并适配命名空间；`NOTICE` 保留 WebDAVManga 来源说明及 PanelsPlus 的版权和 MIT 许可。安装包文件清单纳入新模块。

## 5. 哔哩哔哩接入方案与设计

| 方案 | 收益 | 约束 |
| --- | --- | --- |
| A：独立官方接口适配器（推荐） | 与现有站点接口统一，便于处理会话、权限和过期图片地址 | 当前接口失败原因及可读章节协议必须先验证 |
| B：扩展现有 HTML 规则 | 首页有服务端内容，可利用部分现有解析 | 动态详情与账号授权仍需接口，单独使用不能覆盖阅读要求 |
| C：增加中间服务转接 | 可把部分处理移到服务器 | 增加部署、凭据存储、运维与费用，超出最小实现范围 |

推荐 A。验证完整链路后，内置站点提供列表、搜索、详情、章节、预览和正文阅读，适配现有收藏和阅读历史。当前接口失败先作为前置验证项处理；不能用空列表掩盖失败，也不能把扫码成功当成正文阅读已通过。

### 登录与账号

- 站点设置增加“哔哩哔哩账号”：未登录显示“扫码登录”；已登录显示昵称、UID、验证状态，以及“重新扫码切换账号／退出登录”。
- 二维码在本机绘制，页面有状态、重新生成和返回按钮。每次成功响应后再安排下一次轮询，遵循官方2秒间隔，同一时刻最多一个请求。页面关闭、离开站点或二维码重建会取消旧轮询。
- 状态为生成中、等待扫码、等待手机确认、验证账号、已登录、过期或请求失败。网络失败给出重试，不无限轮询。即使官方未返回过期状态，本插件也在5分钟后停止本次等待并提示重新生成；这是本地等待上限，不声称官方二维码有效期为5分钟。
- 扫码返回的会话先作为候选验证账号与漫画服务访问，保存成功后切换当前账号；切换失败保留旧账号。具体漫画服务登录衔接以官方响应验证结果为准。
- 账号会话单独管理，只向明确列出的官方账号和漫画 API 主机发送必要凭据。CDN 图片请求不携带账号 Cookie；重定向逐步核对目的主机。
- 退出登录清除当前本地会话，取消账号相关请求并更新界面。缓存继续受账号隔离，后续登录另一账号不能误用前一账号的授权图片。
- 使用现有本地设置存储方式，界面不显示原始 Cookie，日志仅记录操作、阶段和安全错误类别。会话保存失败不能显示“登录成功”。

### 图片、权限与缓存

优先使用官方已确认的封面缩图；沿用本地封面和正文缓存。列表与详情的相同封面复用，详情预览复用对应正文原图。

如果图片接口返回有时效的地址，下载时解析，并允许失败后有界更新一次。稳定图片身份采用站点＋漫画＋章节＋图片资源ID＋账号隔离标识，临时签名只用于传输。现有 Zero 和自定义站点的缓存规则保持原语义；仅新增有测试证明的接口边界。

阅读按当前账号已有权限处理，未解锁章节明确提示。费用操作需要单独授权，本次范围内的阅读和登录流程不执行自动购买或扣费。

拟新增 `sources/bilibili.lua`、`bilibili_auth.lua`、`bilibili_api.lua` 和独立扫码/账号控制界面；修改 `app.lua`、`source_registry.lua`、站点设置接入点。仅在已验证的图片协议要求下扩展读取/缓存接口，避免把站点特例塞进通用网页解析。

## 6. 分阶段目标与验收

1. **现有图片故障：** 用户断线重启测试v0.8.86后重新连接，读取新增日志，定位具体传输失败。封面、详情预览和首图实机成功才可报告根治；与新功能分开记录。
2. **独立分格副本：** 完成核心复制与适配。运行几何、对白保护、会话取消、跨页/反向、连续失败回退、内存释放和设置保存失败检查；关闭分格时普通阅读不变。
3. **扫码与账号：** 验证现场二维码控件、官方轮询、账号保存、重启恢复、切换失败、关闭后回调失效、退出与凭据主机隔离；需要用户实际扫码验收。
4. **站点阅读：** 查明当前接口失败原因，验证列表/搜索/详情以及一部免费漫画的章节索引、首图、后续翻页、预览和过期地址重试，再加入完整内置站点。账号可读内容需要对应账号实测。
5. **安装与发布：** 根据用户对新版本发布的授权，生成纯程序安装包，备份后安装，回读核对哈希，再发布有准确验收说明的版本。仅桌面通过时标明实机待验证。

验收方法：开启分格，长按整页，检查三个视图、旋转和连续前后翻格，退出恢复；扫码登录后检查昵称/UID、切换、退出；打开哔哩哔哩漫画测试封面→详情→预览→正文；同时复测 Zero。实机确认字体清晰、设置可操作、连续调整不退出 KOReader。
