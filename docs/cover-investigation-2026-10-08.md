# MangaWeb 封面与预览排查记录

## 范围与事实

用户反馈：首页封面持续卡顿，详情封面和预览空白，上一轮修复发生退化。只处理 MangaWeb 图片流程。已有 v0.8.85 刷新设置修复保留。

- 当前 GitHub MangaWeb v0.8.84 指向 916e611，现场运行版本待用户确认；电脑尚未检测到 Kindle。
- 默认启动先构造 ImageLoader/CoverLoader，之后才赋 options.logger。现有阶段日志在正式启动时缺失。这是确定的取证缺口。
- CoverLoader 小图键包含尺寸，下载原图只在当前会话共享；首页切换详情会取消会话，不同尺寸再次下载同一封面。用跨会话回归复现。
- 封面 HTTP:get 内联走 Turbo 界面循环，正文及预览已经有 HTTP:get_file 后台文件通道。封面不应需要界面线程处理完整下载数据。
- 当前真实 Zero 列表解析21本、详情16章、首章196页；三张封面及首张预览均200、约197–404 KiB，电脑直连总耗时约2–3秒。交叉样本不能证明HTTPS普遍更快，保留协议规则。
- 10月3日23个设备封面JPEG缓存有效、约17–38 KiB；这是历史事实，不能证明当前设备成功命中。
- 现场空白具体停在哪一步尚未确认，不能宣称已根治。

网络取证仅保存在本机 handoff/device-diagnostics/2026-10-08-mangaweb-cover；不提交账户、Cookie、漫画网址、网页和图片。

## 三个方案

1. 增加并发：已有6下载、2处理；不消除重复下载，可能放大设备资源占用。
2. 推荐：复用现有 PageCache/HTTP:get_file，为封面建立稳定的原图标识；保留按尺寸保存的小图，完善真实启动日志。范围小、可回退、无新依赖。
3. 图片代理：可以改变传输尺寸，但增加服务与费用，当前站点未提供经验证的小图入口，不采用。
