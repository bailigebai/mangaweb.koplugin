# v0.8.90 Zero 网络恢复测试版

## 当前结果与改动

本版修复两个已复现的恢复流程问题，仅修改MangaWeb的图片加载器与请求传输层，没有改动WebDAVManga或灰度插件。

- Zero公共CDN的HTTP图片请求遇到传输失败或超时后，在原有第二次尝试中升级为同地址HTTPS。总次数仍为两次，使用原缓存身份，恢复成功后重开可复用缓存。
- 恢复只适用于 `tupa.zerobyw33.com` 的无Cookie/Authorization请求。其他站点、自定义主机、相似主机名、明确HTTP权限拒绝不改写；不降级HTTPS。
- LuaSec原地修改请求表并添加私有 `create` 字段，可能导致HTML空响应的下一次恢复被客户端拒绝。现在每次调用客户端时传入独立请求表。

正常下载路径、并发、总超时、原图画质、分格和缓存保留原有行为。不引入新依赖或代理服务。

## 验证证据

1. 两项新增回归在已发布v0.8.89的源码上失败，在修复后的源码上通过。图片回归使用真实Http、Transport、FileTransport、FileSink和ImageLoader，文件sink实际写盘；网络端点和后台调度使用替身。
2. 源码62组Lua规格、85个Lua文件语法检查通过，包含固定版本像素缓冲与真实GrayDither共享Session契约。
3. 10月11日电脑只读请求Zero列表、详情和章节页面，分别解析21部漫画、12个章节、42张图片地址。同一首图通过HTTP和HTTPS均返回200，393,886字节、JPEG签名；耗时分别1.297秒和1.500秒。凭据来自本机旧备份，未进入源码或安装包。
4. 一次独立代码复核无Critical/Important问题。非阻塞事项：没有新增首请求尚未回收时取消的交错时序测试，不把同步替身通过当作所有设备时序已经覆盖。

最初共享灰度联测使用了错误的外部测试根目录，因缺少辅助文件中止；更正为保存完整固定版本夹具的目录后，完整62组规格通过。没有修改灰度产品文件来绕过检查。

## 安装与验收

退出KOReader，备份旧插件，解压 `mangaweb-0.8.90.zip`，将 `mangaweb.koplugin` 内程序文件覆盖到 `koreader/plugins/mangaweb.koplugin/`。保留原 `cache` 及KOReader设置目录，再重启KOReader。

用原来失败的Zero漫画测试：封面与详情预览、尚未缓存的章节首图、连续翻页、失败后重试、退出后重开。无须全量清除账号、收藏或缓存。仍失败时保留当次 `crash.log`，以便区分连接、TLS、超时、图片处理和界面交付。
