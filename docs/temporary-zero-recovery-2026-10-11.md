# Zero 网络恢复修复计划

用户要求设备无法连接时继续修复并发布；本轮只处理 MangaWeb，Bilibili 章节仍未完成，WebDAVManga 不作修改。

## 事实与限制

此前设备日志有首图与预览成功，也有未分类的传输失败。最近一次截图只有 `transport_error` 文案，没有相应新日志，不能确定截图的底层原因。v0.8.83 至 v0.8.89 的 Zero 地址解析一直把协议相对的 tupa 图片转为 HTTP，加载器第二次尝试仍使用原地址。已读设备 LuaSec 1.3.2 源码证实请求函数原地添加 `create`，又拒绝调用方携带 `create`；当前 HTML 空响应恢复复制的是已经传入过客户端的表。

## 方案比较与采用范围

1. 全部 Zero 图片改成 HTTPS：简单，但改变所有正常下载，TLS 失败时也无恢复路径。
2. 推荐：保留正常路径，在已有第二次文件下载重试中，仅将 Zero 公共 tupa CDN 的 HTTP 地址升级到同地址 HTTPS；隔离 LuaSec 请求表的原地修改。最多仍下载两次，不增加 UI 同步请求，不降级 HTTPS，不转发账户凭据。
3. 增加代理服务：有额外部署、费用和凭据流转，超出此次修复范围。

此为现有下载边界的最小修复，不引入新模块、运行时或设置。
