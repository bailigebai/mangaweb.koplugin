`0.8.71` 修复授权成功后点击“开始阅读”仍停留在漫画详情页的真机根因。MangaWeb 主页面是 KOReader 模态全屏窗口，而内嵌图片阅读器此前是普通窗口；KOReader v2026.07.1 会把普通窗口插到已有模态窗口下面，因此阅读器加载页虽然创建成功并返回 `opened=true`，实际始终被详情页遮住。本版本将阅读器及其阅读控制菜单统一为模态层，保证窗口顺序为 `MangaWeb 根页 → 阅读器 → 阅读控制/跳页输入框`；退出阅读后仍返回原漫画详情页，不重建或丢失浏览状态。

`0.8.70` 修复网络正常时激活仍必定提示“HTTPS 失败”的真机根因。KOReader 自带 LuaSec 1.3.2 的客户端 `sni(host)` 成功时不会返回 Lua 值，旧代码却要求其返回 `true`，因此在 TLS 握手和请求发送前就由插件自身误判失败。本版本改为只在 SNI 调用抛出异常时拒绝连接；CA 信任链、TLS 握手、证书主机名匹配、固定授权域名和失败关闭策略均保持不变。回归测试使用 LuaSec 的真实无返回值约定，防止再次退化。

`0.8.69` 修复真机授权始终提示“本地保存失败”的实际根因。KOReader 自带的原生 RapidJSON 会为解码后的 JSON 对象附加 `json.object` 元表，旧安全校验却把任何带元表的表都当成非法数据；授权文件写入后在回读验证阶段因此被插件自身拒绝并清理，电脑测试使用无元表的 JSON 替身，未能复现。现在只接受普通 Lua 表或 RapidJSON 明确标记的对象表，仍拒绝数组、任意元表、重复键、未知字段和无效签名；测试环境也已改为模拟真机对象/数组元表，覆盖授权文件回读、服务器 receipt 和设备身份恢复三条路径。

`0.8.68` 修复真机首次授权仍提示“本地保存失败”。设备取证确认 KOReader 自身的 `settings/mangaweb.lua` 可以正常直写，但授权文件和临时文件均未留下，失败发生在联网前的首次身份保存；授权存储此前额外要求“写临时文件后重命名”，与 KOReader 官方 `LuaSettings` 的直接持久化路径不一致。本版本改为使用 KOReader 同款目标文件直写：强制刷新后重新读取并逐字节比较、解析 JSON，任何写入或回读失败都会恢复原内容或移除未确认的新文件。RSA 签名、设备绑定和篡改拒绝保持不变。

`0.8.67` 修复部分 Kindle 首次激活时提示“本地保存失败”。KOReader 设置目录所在的用户存储在部分机型上不支持目录 `fsync`，旧实现却把这一可选耐久性操作的失败当成整个授权保存失败。本版本与 KOReader 自身写入策略保持一致：仍强制刷新临时文件、原子替换目标文件，并重新读取、逐字节比较和解析 JSON；目录同步继续尝试，但文件系统不支持时不再拒绝已经回读验证成功的凭证。RSA 签名、设备绑定和篡改检查均未放宽。

`0.8.66` 修复首次激活错误显示“授权存储不可用”。KOReader 在读取尚未创建的文件时会返回 `nil` 和系统的“文件不存在”错误文本，旧实现把它当成存储损坏并拒绝创建授权身份。本版本通过独立的路径存在性检查区分“首次使用、文件不存在”和“文件存在但读取失败”：前者会安全创建 `settings/mangaweb-license.json`，后者仍保持失败关闭且不会覆盖原授权文件。保存后继续执行原子替换、目录同步、重新读取和签名验证。

## 安装

将发布 ZIP 中的 `mangaweb.koplugin` 文件夹复制到 `koreader/plugins/`，重启 KOReader，在主菜单打开“漫画网站”。插件不依赖 Moon，也不使用 NAS、Docker、电脑伴侣、Chromium 或 JavaScript。

若需本版灰度与全刷，将 `graydither.koplugin` 0.3.0 同样放入 `koreader/plugins/` 并启用，然后在正文的“设置 → 灰度与全刷”开启。安装或更新步骤见 [INSTALL.md](INSTALL.md)。开发环境可用 `python scripts/build_package.py` 在本仓库的 `dist/` 构建并校验安装包，不会启动插件或执行授权。

首次打开进入独立的原生“站点中心”；进入过站点后，下次直接恢复该站点的发现页。主页面底部固定显示“发现 / 收藏 / 页码 / 历史 / 我的”：

1. 选择 Zero 进入发现页；在“我的 → 站点管理”点“新增自定义站点”，按四组表单填写域名和规则。WNACG 不会自动出现在站点列表，若需要使用，请自行添加。
2. 每个站点有独立的“进入”和“设置”。Zero 支持账号密码登录和 Cookie；自定义站点支持导入该站点的浏览器 Cookie 和“测试连接”，不提供账号密码表单。Zero 的域名在其设置页修改；修改后旧域名的 Cookie 不会发给新域名。
3. 自定义规则使用 Lua 模式，不执行 Lua 代码。列表路径例如 `/list?page={page}`，搜索路径可留空，或填写 `/search?q={query}&page={page}`；“漫画块”例如 `(<article.-</article>)`，其余规则用括号捕获详情链接、标题、封面、详情标题、详情封面和阅读图片地址。若详情页列出章节，需同时填写章节块、链接与标题。若阅读图片位于脚本数组，可用“图片数组范围”先截取数组，再用“图片地址”逐项捕获。规则须按目标网页实际结构填写；保存只校验格式，随后用“测试连接”验证列表解析，再打开详情和阅读逐步验收。
4. 发现、收藏、历史和分类内容使用白底四列三行封面网格；Zero 的分类和标签仍从“筛选”进入。自定义站点没有对应规则时不显示筛选入口，也不会提供无效搜索操作。网络失败时可在内容区重试，底部导航和返回保持可用。
5. 点击封面进入详情；预览位于标签和简介之前，章节每行 6 个并自动换行。选择章节后点“开始阅读”或“继续阅读”。
6. 阅读时点击左右区域翻页，点击中间显示或隐藏控制层；顶部页码打开数字跳转，右上角设置可调整预加载、方向、显示模式、长图拆分、去灰和亮度/对比度，也可重试、退出或直接回到书架首页。

7. 详情页点“收藏”，选择“默认”或一个自建分类；同一本漫画只能在一个自建分类中。收藏页顶部点“默认”查看全部收藏，点分类名称查看该类漫画；“更多分类”可选择未显示在顶部的分类。“管理分类”可新建、重命名或删除分类。点“多选”，勾选多本漫画，再点“调整分类”统一移动。右上角叉号会先弹出退出确认。

收藏、分类架和历史只保存于 Kindle 本地 SQLite；不会修改网站远端收藏，也不做整本离线下载。阅读产生的会话临时图片在退出阅读器后清理；阅读页的滚动图片缓存保留在插件目录，达到上限后自动按顺序清理。
当前历史表不记录章节：默认章节会恢复页码；非默认章节从第 1 页开始，也不会覆盖默认章节进度。

## 尚未验证的发布门禁

KPW6、KOReader v2026.07.1 的实际绘制和输入、Zero 当前域名登录与首图、自定义站点真实页面规则、图片 CDN、浏览器 Cookie、不同网络以及长时间阅读内存表现均尚未验证。首页可访问只表示公开页面可达，不能代表这些链路通过。此前提供的浏览器 Cookie 没有写入项目、测试或安装包。

## KPW6 验收

在 KPW6 + KOReader v2026.07.1 上检查：

1. 打开“漫画网站”，站点中心不闪退，Moon 原入口仍可用。
2. 进入 Zero，验证配置、分类、标签、搜索、分页和封面布局；修改 Zero 域名后再次测试连接。新增一个自定义 HTTPS 站点，填写规则并测试连接，验证它在“我的”中能编辑和删除；站点列表不应自动出现 WNACG 或 nhentai。
3. 点击封面查看详情，确认章节每行 6 个、最后一行不出现空按钮；切换章节并阅读两页，点击顶部页码跳页，再从右上角设置调整阅读参数或退出阅读。
4. 从历史重新打开默认章节，确认恢复到上次页码；在详情页收藏到自建分类，在收藏页切换“默认”和分类，批量移动两本漫画，重命名和删除分类后确认漫画仍在“默认”收藏中。
5. 在 Zero 搜索《渴盼已久的恶役千金》并点“开始阅读”：首图能正常显示；若下载停滞，约 25 秒无新进度后应出现“图片加载超时”及“重试”，不再停留 5 分钟。分别试取消和确认右上角退出弹窗。

桌面规格不能替代真机结论；真实站点结构、TLS、Cloudflare 和图片 CDN 仍需按站点分别验收。

## 实网门禁

桌面规格使用本地 HTML 样本验证自定义站点列表、详情、章节和阅读图片解析。真实站点需在 Kindle 上按上面的步骤逐页验收；自定义规则会随网页结构变化而需要人工调整。插件不会自动绕过 Cloudflare、验证码或付费墙。

网络取消目前保证“立即忽略回调并清理阅读状态”。KOReader 的同步 LuaSec HTTPS 请求期间主线程不能处理新的取消事件，底层连接仍受 socket 超时约束；插件不承诺 HTTPS 物理连接即时断开。
